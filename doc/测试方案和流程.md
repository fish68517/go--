# 测试方案和流程

本文档用于验证《技术实现方案.md》中已经实现的新增功能：

1. 处方选择药材时可以选择进货源地、入库批次，并保存到处方药材明细。
2. 处方详情可以生成药材价格明细表。
3. 处方详情可以模拟支付，不接入真实支付。
4. 溯源查询可以显示药材进货源地、批次、支付信息和上链信息。
5. 煎药过程数据可以点击上链，并记录上链状态。
6. `dapingzhanshi` 大屏可以看到当天新建处方。

## 一、测试前准备

### 1. 启动 MySQL

确认 MySQL 已启动，并且已经导入数据库。

本项目当前数据库配置：

```text
数据库名：hgy
账号：root
密码：root
```

配置文件位置：

```text

```

### 2. 启动 Go 后端

安装 64 位 Go 后，打开 PowerShell：

```powershell

go run main.go
```

后端默认地址：

```text

```

浏览器打开：

```text

```

登录账号：


### 3. 启动大屏项目

另开一个 PowerShell：

## 十二、常见问题和判断方式

### 1. 处方录入时“进货源地”下拉框显示“暂无入库批次”

可能原因：

- 没有先做入库。
- 入库药品编码不是 `RS001`。
- 处方药品编码输错。
- 输入编码后没有让输入框失去焦点。

处理：

1. 回到“库存管理 -> 入库管理”确认入库详情。
2. 确认药品编码是 `RS001`。
3. 回到处方录入，重新输入 `RS001` 后点击页面空白处。

### 2. 价格小计不对

计算规则：

```text
总剂量 = 单剂量 * 贴数
小计 = 总剂量 * 单价
```

示例：

```text
3 * 2 * 2.50 = 15.00
```

### 3. 模拟支付按钮不显示

原因：

- 该处方已经支付，状态是 `PAID`。
- 详情页没有加载到支付记录。

处理：

1. 重新打开详情页。
2. 查询 `prescription_payment` 表。
3. 如果已经是 `PAID`，按钮不显示是正常的。

### 4. 上链失败

先看错误内容：

- 如果是网络连接失败，通常是外部链服务不可用。
- 如果是 `未知字段: "medicines"` 或 `未知字段: "payment"`，说明上链 payload 兼容性有问题，需要重新检查 `UploadChain`。
- 如果是处方字段为空，检查处方是否有处方号、接方时间、流程数据。

### 5. 大屏看不到新处方

重点检查：

1. 新处方日期是否是今天。
2. 大屏是否连接 `http://127.0.0.1:9090/buss/bigscreen`。
3. Go 后端是否正在运行。
4. 浏览器直接访问大屏接口是否包含该处方号。

### 6. 不要用“处方扫描”页面测试本次新增功能

“处方扫描”页面属于煎药流程扫描，代码按业务角色判断权限。

如果用 `admin` 账号扫描，可能提示：

```text
无扫描业务权限
```

这不是本次“源地、支付、上链、溯源、大屏”功能的测试入口。

本次功能主要使用：

```text
库存管理 -> 入库管理
业务管理 -> 处方管理 -> 处方录入
业务管理 -> 处方管理 -> 接方信息
业务管理 -> 区块链业务管理 -> 煎药过程数据上链
业务管理 -> 区块链业务管理 -> 智慧中药溯源
```

## 十三、验收通过标准

按上面流程测试后，如果满足以下结果，可以认为新增功能基本实现：

- 入库详情能看到“进货源地”和“供应商”。
